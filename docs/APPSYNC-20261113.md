# Uke AppSync 合入（2026-11-13）

来源为 UniXNU-sheng `c3c7468ad9f719b54f1011bd3bb01eea25a5ed5a` 与
`20cf25def67cc12ef9339553294e1617b7d9e94e`。core 已有 `7fdf1e6`、`5f7172b`
对应的 AppSync 适配器和进程内 ldid 签名库，不重复引入。

`sheng-appsync-user-trust.patch` 与 sheng 当前实现一致；runtime 补丁仅将插入位置
调整到 Uke 背光挂载之后。库挂载成功才覆盖 installd、backboardd、安装 helper 和
CoreServices。SpringBoard.app 保持普通目录，不直接将卷挂在应用包根目录。
签名结构和页哈希检查继续运行；动态注册的用户应用在 exec 后使用第三方进程身份。

板级开启 `appsync=1`，Linux 继续显式准备 runtime，保留原 Data seed。
`scripts/build-appsync-runtime.py` 调用 core 原始 builder、签名器和已固定依赖，
仅适配 Linux 编译工具与 ldid 签名接口；独立校验 SHA256/4KiB 页、标识及 entitlement。
四个系统服务使用既有 category 5，库及安装命令使用 category 0；原 trust modules
和 addon 文件逐字节保留。新 backboardd 同时包含原有 BacklightMode 和 UkeBrightnessTransactions。
独立背光覆盖仍保留，`appsync=0` 时可使用原路径。

core 签名器源清单修正：libplist 的 libcnary/Makefile.am 只编译 node.c 和 node_list.c；
cnary.c 是带 main() 和过期指针接口的演示程序，不能加入正式静态库。

构建入口：

```sh
python3 scripts/build-appsync-runtime.py --os-root /readonly/24A446/OS \
  --output /path/to/runtime --addon /path/to/previous/gpuaddon.bin \
  --trust /path/to/previous/owner-trust.bundle
```

将新 addon/trust 成对传入 core，执行正式 kernel 和 payload 构建。无需重建或写入
userdata。设备启动后，可由已有设备终端运行：

```sh
/usr/libexec/unixnu-appinst /path/on/device/Example.ipa
```

合入构建阶段未操作设备。安装、首次启动、更新、嵌套框架与重启后保留须由 Uke 实机分别验证，
同时回归 Wi-Fi、亮度和熄亮；sheng 的实测不能视作 Uke 验收。
工作区候选和验证记录见 `../../docs/status/appsync-2026-11-13.md`。

后续实测：首包 `0d3444d4…` 三次 backboardd 缺 NSConstantDoubleNumber，进入 recovery
卸载后发生 vnode 引用计数 panic，已标 DO_NOT_FLASH。Linux ld64 对重复库保留第一次的
普通依赖声明，故必须只给出 Foundation 重导出声明；core 与板级 builder 均检查最终
LC_REEXPORT_DYLIB 和头标志。SpringBoard 没有足够的头部空白，不能把四个服务统一改为追加依赖。
